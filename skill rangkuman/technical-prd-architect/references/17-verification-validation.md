# Verification and validation

## Review guidance
Verification proves requirements implemented; validation proves user problem addressed. Build a matrix with test ID, requirement, method, setup, stimulus, expected result, observed result and evidence. Mark unrun tests explicitly; include boundary/failure, performance, security and safety tests.

## Output contract
Record confirmed evidence, any proposed additions, unresolved TBDs, requirement IDs and the verification method. Distinguish direct source facts from recommendations.
