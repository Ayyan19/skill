# PRD fundamentals

## Review guidance
Use version, owner, purpose, context, goals, non-goals, user needs, scope, features, measurable requirements, interfaces, risk, milestones and acceptance. Adapt section depth to project complexity. Separate product PRD from implementation design and label attached architecture as a candidate design.

## Output contract
Record confirmed evidence, any proposed additions, unresolved TBDs, requirement IDs and the verification method. Distinguish direct source facts from recommendations.
