# Requirement engineering

## Review guidance
Each requirement: stable ID, statement, rationale, priority (MoSCoW), user/trigger, measurable acceptance, verification, dependencies, status and source. Avoid combining unrelated conditions in one ID. Capture boundaries, failure states, timing, units and traceability. No arbitrary threshold without context.

## Output contract
Record confirmed evidence, any proposed additions, unresolved TBDs, requirement IDs and the verification method. Distinguish direct source facts from recommendations.
